## 更新与发布

1. 将审核过、可以公开的报告加入日期目录。新命名格式为 `YYYY-MM-DD/HH-MM-SS-【类型】-summary.md`，现有下划线文件名保持不变
2. 正文保留原始观察时间、来源链接、成本假设和风险提示。文件名时间为报告发送时间，不替代数据观察时间
3. 可在 `metadata.json` 以完整路径为键补充 `type`、`tags`、`summary`、`observation`；文件名中的类型优先
4. 本地运行 `node scripts/build.mjs` 和 `node scripts/test.mjs`。生成的 README 和 reports.json 可一并提交
5. 提交到 main 后，GitHub Actions 自动重新扫描公开 Markdown、生成静态页面并部署 GitHub Pages。线上 reports.json 始终由构建生成

仅日期目录中符合上述新旧格式的 Markdown 会进入网页。站点不需要后端、访问令牌或私有仓库读取权限。

页面源码：`scripts/` 与 `assets/`；生成目录：`_site/`（不提交）。
